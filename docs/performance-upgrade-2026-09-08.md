## 注意力优化：用户重启后已确认启用

安装版本 VoxCPM 2.0.3、Torch 2.8.0+cu129。现有语音模型已经在 CUDA 上使用 bfloat16，VAE 按原包使用 float32；并非误跑 CPU。现有 `optimize=False`，本机未安装 Triton，不能直接打开编译开关假定提速。

已安装 eager MiniCPM 每步原本将整段 8192 长度 KV 交给 masked SDPA。新增项目内 `voice_attention_patch.py`，仅给本模型 base_lm/residual_lm 的两个缓存实例返回已填充位置的共享视图，不修改虚拟环境、权重、dtype、采样步骤、随机采样、原 mask、原写入或原缓存容量。

关键顺序已经独立复核：调用先 `step()`，因此 `current_length = position_id + 1`，视图包含当前写入位置；删除部分在原 mask 中全为 False。mask 由 key 长度建立，切片后维度一致。每句/retry 的 prefill 重置缓存，参考音频特征缓存不受影响；保留 generation_lock。版本、相关方法源指纹、接口或未编译条件不符则自动恢复原方法。

验证：真实两层 MiniCPM 的 CPU 短/中/长/满缓存、连续 step、prefill/reset、共享存储、撤销、guard 及运行异常恢复测试通过，最大绝对误差 `3.576e-7`。一次小型 CUDA 测试（hidden 64，两层，BF16）由 5.8949 ms 降至 5.4384 ms，约 1.084 倍，输出最大误差 0。**这是小模型计算环节的基准，不是完整 VoxCPM 语音的提速结果；也不能保证生成音频逐样本一致。**

`voxcpm_voice_service.py` 已加最小加载 hook。用户手动重启后，语音 `/health` 已确认 `ready: true`，`attentionOptimization` 为 `enabled: true, patchedCaches: 2, reason: filled-kv-views`。
