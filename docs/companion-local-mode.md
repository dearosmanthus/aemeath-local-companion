# 本地大脑试用

当前版本仅支持本地，`config.json` 和默认配置模板的 `llm.mode` 均为 `local`。云端配置字段与调用分支已删除。

- 对话：已安装的 Qwen3.5-9B-Q5_K_M，由 llama.cpp 在 `127.0.0.1:1235` 提供服务。
- 识别：原本的本机 SenseVoice；声音：原本的本机自然语音服务 `127.0.0.1:17861`。
- 形象：原本的本地 PMX 3D 舞台；本轮未改模型文件、声线或表演算法。

运行 `Start-Desktop-Companion-Services.ps1` 会按本地模式启动大脑。页面仍为 <http://127.0.0.1:17860/stage/>。当前大脑使用 CPU 推理，生成线程 8、提示词处理线程 12，为桌面和声音保留余量；没有额外加载 GPU 大脑。

## 本地模式的网络约束

伴侣服务器的 HTTP 请求统一经过 `lib/companion-network.js`，无条件只允许 HTTP 回环地址，禁止跟随重定向；即使误填外部模型或语音地址，也会报错而不是发送对话。聊天、健康检查和预热均不包含云端分支，本地模型失败不会回退到第三方 API。

启动脚本不读取云端密钥存储，并清除子进程将继承的常用聊天 API 密钥变量；不会删除用户保存的密钥。上述约束仅针对此伴侣服务，不是整台电脑的防火墙，也不改变 Codex 或其他应用的联网方式。

v2 补强：服务启动前校验所有配置目标，仅允许配置过的回环接口；禁止认证/Cookie 请求头，直接 Node 启动同样清除本进程内的常用 API 密钥变量。HTTP 和 WebSocket 拒绝来自其他网站的请求，WebSocket 客户端必须提供 `http://127.0.0.1:17860`（或同端口 localhost / IPv6 回环）的 Origin；浏览器会自动提供，无需用户填写。

## 验证与重启

`npm run test:local` 用替身网络函数验证外部 URL 被阻止，不产生实际外网请求。`/api/health` 的 `llm.provider` 应为 `local`，`llm.expected` 为 `local-companion-model`。

新版启动入口先检查 `/api/runtime` 的 `security.policy` 为 `loopback-only-v2`、`credentials` 为 `disabled`，此检查不请求大脑或语音服务。旧版本仍占用 17860 时会提示停止旧伴侣再启动，不会自动结束未知进程。大脑服务可能仍需预热；运行标记通过不代表模型已准备好。

修改 `config.json` 后必须重启 17860 伴侣服务器才能生效。不要用查日期作为唯一对话测试：日期由程序直接回答，不会证明模型可用。

旧的云端模式已移除，修改模式字段不会重新启用它，只会拒绝启动。若将来确需云端功能，必须另行明确服务方、发送内容和专用凭据，再独立实现，不能复用其他应用的凭据。

## 本地请求层整理

模型和自然语音 HTTP 协议集中在 `lib/local-services.js`，主服务器不再拼接模型请求或重复实现健康检查。客户端构建时快照经过校验的模型/语音设置，不读取其他文件或环境变量。`/api/health` 并行检查两个本地服务，保留原有前端数据格式。

对话流支持中文 UTF-8 分包、跨包的思考标签、无末尾换行的最后一帧及 `[DONE]` 结束；只将可见台词交给字幕，不将思考段作为台词。取消时停止已缓冲帧，生成和合成请求有 120 秒超时。错误不会触发其他服务商回退；原有本机 Kokoro 备用声线逻辑保留。

本轮验证仅使用离线替身和语法/骨骼测试，未重启服务或发送真实对话，也未改动形象资源与声线。后端运行验收仍需正常重启后另行完成。
